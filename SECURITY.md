# 🔒 Security Policy

Thank you for helping keep the AI Magic Invisibility Portal safe and magical. ✨ This document explains how to report security vulnerabilities responsibly and what to expect after you do.

---

## 🛡️ Reporting a Vulnerability

**Please do NOT report security vulnerabilities through public GitHub issues.**

Instead, please report them privately using one of these channels:

1. **GitHub Private Vulnerability Reporting** (preferred): open the repository on GitHub → **Security** tab → **Report a vulnerability**.
2. If that is unavailable, contact the maintainer (@sanya-1612) directly to arrange a private discussion.

When reporting, please include as much of the following as you can:

- A clear description of the vulnerability and its impact
- Step-by-step instructions or a proof-of-concept to reproduce it
- The affected version/commit (`git rev-parse HEAD` output works)
- Any relevant logs, screenshots, or stack traces
- Your suggested fix, if you have one

---

## 📬 Responsible Disclosure Process

1. **You report** the issue privately through one of the channels above.
2. **We acknowledge** your report within **5 business days**.
3. **We investigate** and assess the severity, keeping you updated on our progress.
4. **We develop and test** a fix. We may ask you for additional details along the way.
5. **We release** the fix and publish a public advisory (with credit to you, unless you prefer to remain anonymous).

Please give us a reasonable amount of time to address the issue before any public disclosure.

---

## 🗓️ Supported Versions

This project is an early-stage application distributed via this repository only — there are no packaged releases yet, so there are no formal version branches.

| Version | Supported |
|---------|-----------|
| `main` branch | ✅ |

Always run the latest code from the `main` branch to pick up security fixes.

---

## ⏱️ Response Timelines

| Stage | Target |
|-------|--------|
| Acknowledgement | Within 5 business days |
| Initial assessment | Within 10 business days |
| Fix for critical issues | As fast as possible, prioritized |
| Fix for other issues | Next regular update |

These are best-effort targets for a community-maintained project — we appreciate your patience. 🌱
